 Intern Full-Stack Development Assignment
 Frontend + Backend | User, Admin, Wallet, Connections, Video Call & AI
Level: Intern    |    Goal: Build a simple working full-stack application
1. Project Overview
Build a simple web application with two types of users: User and Admin. The application should allow users to create an
account, subscribe, receive money/credits in a wallet, connect with other users, make video calls, upload documents, and
ask questions about their documents using Google Gemini AI. The Admin should be able to monitor users and their
usage.
2. User Types
 User
Can register/login, subscribe, view wallet balance, connect with other users, make video calls, upload
documents, and ask AI questions.
Admin
Can view users, subscriptions, wallet/credits, AI usage, documents, connections, and basic activity.
3. Main Requirements
A. Authentication
  User registration with name, email, and password.
  User login and logout.
  Password should be stored securely using hashing.
  Admin should also have a separate login or admin role.
  Only logged-in users can access user features.
 
B. Subscription & Wallet
  Create at least 2 simple subscription plans.
  User can select a subscription plan.
  After subscription, add a fixed amount of credits/money to the user's wallet.
  Show the current wallet balance on the dashboard.
  Show a simple wallet transaction/history page.
  For the assignment, real payment integration is optional. A test/mock payment flow is enough.
 
C. Connect With Other Users
  Display a list of users.
  User can click 'Request to Connect'.
  Other user can Accept or Reject the request.
  Show connected users in a separate list.
  Do not allow duplicate connection requests.
 
D. Video Call
  A user can start a video call with an accepted connection.
  Use a simple WebRTC implementation or a suitable free/test video-call solution.
  User should be able to start/end the call.
  Camera and microphone controls are preferred but can be basic.
  Save basic call information such as caller, receiver, date, and duration.

E. Document Upload + Gemini AI
  User can upload a PDF document.
  Show uploaded documents on the user's dashboard.
  User selects a document and enters a question.
  Send the document/question to the backend.
  Use the Google Gemini API to generate an answer based on the document.
  Display the AI answer on the frontend.
  Save basic question/answer history.
  Gemini API key must be stored in the backend environment file, not in frontend code.
 
F. Admin Dashboard
  Admin can see the total number of users.
  Admin can see active subscriptions.
  Admin can see wallet/credit balances.
  Admin can see credits/usage spent by users.
  Admin can see uploaded documents.
  Admin can see connection requests and basic video-call history.
  Admin should be able to open a user's basic details.

8. Important Rules
  Keep the project simple. Do not over-engineer the solution.
  Frontend and backend must communicate through APIs.
  Validate important inputs on the backend.
  Use environment variables for API keys and passwords.
  Do not put the Gemini API key directly in frontend JavaScript.
  Users must not be able to view another user's private documents or wallet information.
  Admin APIs/pages must only be accessible to Admin users.
  Write clean, readable code and keep the project structure organized.
 
9. Expected Deliverables
  Frontend source code.
  Backend source code.
  Database models and migrations.
  API documentation or Postman collection.
  README with setup instructions.
  .env.example file without real API keys.
  Basic screenshots/demo of the working application.
  A short explanation of the project structure and major features.
 
10. Minimum Working Flow
 1. Register → Login.
 2. Select a subscription → Receive wallet credits.
 3. View other users → Send connection request.
 4. Other user accepts → Users become connected.
 5. Start a video call with the connected user.
 6. Upload a PDF → Select the document → Ask a question.
 7. Backend sends the relevant document content/question to Gemini → Display the answer.
 8. Admin logs in → Views users, subscriptions, wallet balances, and usage.
 
Intern Assignment Objective: Focus on making the complete basic flow work correctly. A simple, clean implementation
is preferred over adding unnecessary advanced features.
